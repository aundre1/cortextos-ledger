# Example: cortextos-ledger inside a CortextOS org

`cortextos-ledger` is a separate repository from CortextOS
(`docs/architecture.md`, "Relationship to upstream CortextOS"). This is what
it looks like once installed for one org, without any of this kit's own
source living inside the org's tree.

```
orgs/
  acme/
    .cortex/
      ledger.db                 created once by `cortexctl init`
      runs/
        t_01h.../
          brief.md
          builder/
            events.jsonl  out.txt  exit.txt  done.marker
            patch.diff    reasoning.md
          reviewer/
            events.jsonl  out.txt  exit.txt  done.marker  verdict.json
          packet.json  packet.md
    cortex-ledger.json           config for this org: db path, limits, providers
    agents/
      blind-reviewer/
        IDENTITY.md  SOUL.md  GUARDRAILS.md  config.json  HEARTBEAT.md
      novice-builder/
        IDENTITY.md  SOUL.md  GUARDRAILS.md  config.json  HEARTBEAT.md
    .claude/skills/cortex-ledger/SKILL.md   (or the harness's equivalent path)
```

`orgs/` is inside CortextOS's own `.gitignore`, and inside this kit's, so
`.cortex/` and everything under a run directory never gets committed from
either side. The only files that leave this tree and enter version control at
all are `cortex-ledger.json` (limits and provider config, no secrets) and the
copied `agents/` and skill files, and only if the org's own repository tracks
its config, which is the org's choice, not this kit's.

## Where each piece comes from

- The three community artifacts (`community/skills/cortex-ledger`,
  `community/agents/blind-reviewer`, `community/agents/novice-builder`) are
  copied in once, per `community/README.md`.
- `cortex-ledger.json` is written by the operator for this org: at minimum
  the `db` path (`./.cortex/ledger.db`, resolved relative to wherever this
  file lives) and the provider quota windows the org actually has.
- Everything under `.cortex/` is generated by `cortexctl` and the harnesses it
  launches. Nothing in it is written by hand.

## How an agent finds this at boot

CortextOS selects a harness per agent through the `runtime` field in that
agent's `config.json`. An agent booted into `orgs/acme/` runs
`cortexctl packet --board --owner <its own name>` first (its `HEARTBEAT.md`
says so) and `cortexctl run:start` before touching any file, exactly as
`community/skills/cortex-ledger/SKILL.md` describes. Nothing about that
sequence is org-specific; only the config path and the agent's own name
change between orgs.
